# RuleLink 검색·공식근거·최신성 구조

## 1. 목표

사용자가 법 이름을 몰라도 평소 말로 상황을 검색하고, 다음 순서로 검증된
법률정보에 도달하게 한다.

1. 상황 또는 정확 식별자를 찾는다.
2. 결론을 바꾸는 사실을 확인한다.
3. 적용 법리·예외·기한·행동을 읽는다.
4. 그 판단에 연결된 공식 문언을 확인한다.
5. 공식 근거가 변경되면 영향받은 판단만 다시 검토한다.

검색 문구마다 글을 만드는 방식과 모든 글을 주기적으로 다시 읽는 방식은
채택하지 않는다. 검색 표현은 검색계층에서 흡수하고, 최신성은 공유 근거와
법률명제 의존관계에서 관리한다.

## 2. 검색 실패를 세 종류로 분리한다

| 구분 | 의미 | 처리 |
|---|---|---|
| 표현 결손 | 관련 법률정보는 있으나 사용자의 표현을 검색기가 이해하지 못함 | 질의 정규화·동의표현·의미검색 개선 |
| 식별자 결손 | 조문·판례번호가 승인 검색범위에 없음 | 출처 수집·정본 편입 작업으로 전달 |
| 판단 결손 | 필요한 법리·사실분기·행동 정보가 없음 | 콘텐츠가 아니라 Rule·Scenario·Source 단위로 보강 |

무결과를 전부 “검색어를 줄여 보세요”로 돌리지 않는다. 화면은 실패 종류를
구분해 설명하고, 내부 품질지표도 각각 별도로 집계한다.

## 3. 검색 구조

### 3.1 현재 구현하는 기본 검색

- 화면에 노출하는 예시는 단일 정본 배열에서 관리한다.
- 노출 예시는 실제 운영 출판본에서 결과와 매칭 이유가 있어야 한다.
- 한국어 조사와 일상적인 종결어미를 원문 토큰을 보존한 보조 표현으로
  정규화한다.
- 부정어·많고 적음처럼 문맥에 따라 의미가 바뀌는 표현은 관련 행동이나
  채무 문맥이 있을 때만 확장한다.
- 비어 있지 않은 검색은 실제 표시 필드에 매칭 이유가 없으면 결과를
  반환하지 않는다.

### 3.2 다음 검색계층

검색 결과의 법률적 권위는 검색점수가 아니라 재수화된 정본에서 나온다.
검색기는 다음 채널의 후보 ID만 합친다.

1. 정확 식별자: 법령명·조문·판례번호
2. 한국어 단어검색: 노리(Nori) 형태소 분석과 비엠25(BM25)
3. 의미검색: 상황·목표·사실분기 문장의 임베딩
4. 관계 재정렬: Rule·Scenario·Source·Hub 연결
5. 정본 재수화: 현재 출판본 또는 활성 SQLite에서 ID와 해시 재확인

단어검색과 의미검색은 상호순위결합(RRF)으로 합친다. 검색 색인의 문장을
법률근거로 직접 사용하지 않는다.

### 3.3 검색 품질 자료

다음 자료를 서로 다른 분모로 관리한다.

- 노출 예시: 배포를 차단하는 수락시험
- 정답 질의: 반드시 특정 판단·근거로 연결되는 질문
- 반대 질의: 비슷해 보여도 반환하면 안 되는 질문
- 무결과 질의: 표현 결손·식별자 결손·판단 결손으로 분류
- 재검색·선택 자료: 개인정보를 제거한 집계만 사용

콘텐츠 수는 성공지표가 아니다. 판단축 회수율, 필수 근거 회수율,
무결과 분류율과 사용자가 올바른 다음 행동에 도달했는지를 측정한다.

## 4. 공식 문언 표시

공식근거 카드는 항상 다음 둘 중 하나의 상태를 표시한다.

1. `verified_text`: 이 글이 참고한 출처 버전과 저장 문언의 해시가
   일치한다. 확인한 조문 문언을 카드 안에 표시한다.
2. `link_only`: 버전이 정확히 결박되지 않았거나 판례·공식문서여서
   페이지 안에 직접 표시하지 않는다. 이유를 숨기지 않고 공식 원문으로
   연결한다.

같은 법 이름과 조문번호라는 이유만으로 현재 문언을 과거·미래의 출처
버전에 대신 붙이지 않는다. 원문을 더 많이 보여주기 위해 버전 검증을
약화하지 않는다.

사용자 화면에는 내부 스냅샷, 해시, 패킷 같은 구현용 표현을 노출하지
않는다. “저장된 원문과 버전이 일치한다” 같은 시스템 설명보다
“확인한 조문 문언”과 “공식 원문에서 확인”이라는 행동 중심 표현을 쓴다.

## 5. 최신성·근거 점검 구조

### 5.1 공유 영수증

페이지별 점검일을 독립적으로 만들지 않는다. 하나의 공식 출처를 여러
콘텐츠가 사용하면 출처 검토 영수증 하나를 공유한다.

- 문언 해시가 결박된 출처: 180일 장기점검
- 좌표만 확인된 출처: 90일 장기점검
- 출처 버전 변경: 장기점검일과 무관하게 즉시 무효화

콘텐츠의 다음 점검기한은 연결된 공유 근거 중 가장 빠른 기한이다.

### 5.2 증분 작업 큐

출처마다 하나의 작업을 만들고 전체 콘텐츠 ID를 큐에 복제하지 않는다.
큐에는 좌표, 예상 버전·해시, 점검기한, 점검방법과 역의존 선택자의
개수·해시만 기록한다. 실제 영향 대상은 점검 시 유지보수 색인에서
다시 해석한다.

변경감지 단계는 다음만 수행한다.

- 공식 좌표 해석
- 버전·시행일 비교
- 정규화 문언 해시 비교
- 연결과 응답상태 검사

이 단계의 모델 사용 허용값은 `false`, 토큰 예산은 `0`이다. 변화가 없는
출처는 새 콘텐츠 검토작업을 만들지 않는다.

### 5.3 변경 후 검토

문언 변경이 확인됐을 때만 조·항·호 차이를 추출하고 역의존 관계를
따라 영향받은 법률명제를 찾는다. 다음 순서로 범위를 줄인다.

`출처 → 조항 → 법률명제 → 사실분기·예외 → 답변 단위 → 콘텐츠`

모델은 변경 의미와 수정 초안을 보조할 수 있지만, 변경 여부·해시·적용
법판과 승인 상태를 결정하지 않는다. 기계 비교 결과와 승인 영수증이
없으면 공개 상태를 갱신하지 않는다.

### 5.4 기준시각과 법판 유효기간

사용자 기기 시계를 법적 판단의 정본으로 사용하지 않는다. 서버가 응답할 때
확정한 기준시각을 내려주고, 법령 버전은 다음 구간으로 판정한다.

`effective_from <= 기준시각 < effective_to`

- 구간 안: 현재 적용 가능한 법판
- 기준시각이 시작 전: 시행예정 법판
- 기준시각이 종료 뒤: 과거 법판
- 시작·종료 좌표가 불완전함: 자동판정 금지, 적용시점 미확정

이 계산은 토큰 없이 가능하며 날짜가 도래할 때 페이지별 재검토를 만들지
않는다. 다만 기준시각은 법령 문언이 실제로 바뀌었는지, 예외·판례·행정해석이
달라졌는지 알 수 없다. 따라서 시간구간 자동판정은 출처 해시 변경감지를
대체하지 않고 앞단에서 불필요한 사람 검토를 줄이는 역할을 한다.

현재 023 공개본의 일반 Source 좌표에는 완전한 `effective_from/effective_to`
구간이 없고, 승인된 Authority 계층도 아직 공개 데이터가 0건이다. 그러므로
현 상태에서 기기 시계만으로 “현행”을 표시하면 거짓 확정이 된다. 024 이후
원장 출판은 법판 구간을 필수화하고, 구간이 닫힌 근거만 자동 현행판정에
사용한다.

## 6. 규모 확장

백만 페이지에서도 비용이 전체 페이지 수에 비례해서는 안 된다.

```text
나쁜 구조: 전체 페이지 × 정기 재검토
목표 구조: 변경된 고유 출처 × 영향받은 법률명제
```

공통 조문 하나가 많은 페이지에 연결되더라도 출처 변경감지는 한 번만
수행한다. 영향 범위가 클 때도 페이지 원문 전체가 아니라 그 조문에
직접 결박된 법률명제부터 검토한다.

현재 규모에서는 유지관리 인덱스의 출처 영수증으로 작업 큐를 실행 시점에
메모리에서 생성한다. 동일 정보를 별도 대형 JSON으로 저장하거나 출판본에
복사하지 않는다. 출처가 수십만 건으로 늘면 같은 계약을 PostgreSQL 또는
SQLite 작업 테이블로 옮기고, `due_at` 인덱스로 실행 대상만 조회한다.
변경되지 않은 출처와 영향받지 않은 콘텐츠는 새 행이나 검토 작업을 만들지
않는다.

## 7. 수락 기준

### 검색

- 화면에 보이는 모든 검색 예시는 결과 1개 이상
- 비어 있지 않은 모든 결과는 실제 표시 필드의 매칭 이유 보유
- 구두점·빈 토큰 질의는 전체 결과로 확장하지 않음
- 부정·예외 표현의 반대 결과 과확장 없음
- 느린 전체색인 로딩 중 거짓 빈결과 없음

### 공식 문언

- 모든 공식근거 카드는 `verified_text` 또는 `link_only`
- `verified_text`는 출처 버전·원문 해시가 정확히 결박됨
- `link_only`는 원문이 있는 것처럼 표시하지 않음
- 모든 외부 원문 링크는 목적이 드러나는 이름과 외부 링크 아이콘 보유

### 최신성

- 출처별 작업 수는 출처 수를 넘지 않음
- 결정론적 변경감지 토큰 예산 0
- 변화 없는 출처는 콘텐츠 검토작업 0
- 변경 출처의 역의존 대상 누락 0
- 점검기한 초과·출처 누락·버전 변경은 공개 검증을 차단

## 8. 구현 단계

1. 노출 예시와 한국어 활용형 검색 계약
2. 무결과 분류와 사용자 안내
3. 공식 문언 두 상태의 일관된 표시
4. 출처 단위 증분 점검 큐와 일일 보고
5. 원천 저장소의 공식자료 변경감지 작업자
6. 법판 유효기간 출판과 서버 기준시각 자동판정
7. 조항·법률명제 단위 역의존성
8. 노리·비엠25·의미검색·관계 재정렬
9. 검색 실패 자료를 이용한 판단 결손 보강

1~4는 공개 저장소가 담당한다. 5~6은 RuleLink 원장·활성 SQLite를 가진
원천 저장소가 담당하며, 서명된 결과만 공개 출판 과정이 소비한다.
