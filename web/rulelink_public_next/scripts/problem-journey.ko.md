# 상황별 문제해결 흐름

## 이용 경로

보증금 주제 페이지의 ‘내 상황에 맞춰 보기’에서 시작합니다. 연결된 상세 글에도 같은 진입 링크가 있습니다. 상황 선택 → 사실 확인 → 조건별 행동계획 → 공식 근거 문언 → 확인 메모의 순서입니다.

선택은 화면 메모리에만 둡니다. 질문 답변을 바꾸면 완료 표시를 비우고 행동의 조건을 다시 계산합니다. 다른 상황으로 바꾸면 이전 사실을 승계하지 않습니다. ‘모르겠음’은 미확인 상태로 요약에 남습니다.

## 다른 주제 추가

1. `src/lib/deposit-problem-journey.ts`처럼 주제 정의를 추가합니다. 주제·콘텐츠 식별자와 상황별 읽기 순서를 선언합니다.
2. 실행 행동에 조건이 필요하면 원문 행동의 콘텐츠·배열 위치·정확한 문장과 필요한 사실분기를 연결합니다. 원문이 변경되면 빌드가 실패하므로 다른 문장을 잘못 실행하지 않습니다.
3. `src/lib/problem-journey-definitions.ts`에 등록합니다.
4. 새 주제의 긍정·부정·미확인 조합, 원문 변경 실패, 내보내기와 실제 브라우저 시험을 추가합니다.

공통 실행기에는 주제별 법률효과를 넣지 않습니다. 질문의 양쪽 결과, 행동, 주의사항, 공식 근거는 출판 정본을 재사용합니다. 문언은 기존 파생 원문 라이브러리에서 버전·해시 검증을 거쳐 제공된 내용만 사용합니다. 원문이 없으면 미수록이라고 알리고 공식 링크를 제공합니다. 미수록 문언을 생성하지 않습니다.

## 컨시어지 연결

미리보기 후 사용자가 명시적으로 복사하거나 텍스트로 저장합니다. 컨시어지에는 URL이나 자동 요청으로 사실을 보내지 않습니다. 승인된 변호사 사용자는 기존 작업공간 진입 조건을 확인하고 새 사건에 메모를 붙여넣습니다. 일반 이용자는 이 메모를 상담할 변호사에게 제시할 수 있습니다. 이 기능 자체가 개인 사건의 결론이나 상담 접수를 제공하지는 않습니다.

## 검증 명령

- `npm run test:problem-journey`: 출판 데이터 연결, 모든 선택 조합, 행동 조건, 내보내기, 변경 실패 시험.
- `npm run build:check`: 기존 출판 안전검증을 포함한 별도 빌드.
- `npm run test:problem-journey-browser`: 위 별도 빌드에서 네 화면 폭·사실 변경·원문·요약 복사/저장·접근성·자바스크립트 없는 안내를 검증.

기존 콘텐츠의 점검기한이 지난 경우 현시각 빌드는 실패합니다. 기능시험용 고정 시각을 썼다면 결과에 반드시 구분해서 기록하고, 그것을 최신 법률 검증이나 운영 배포 근거로 사용하지 않습니다. 점검 날짜를 임의 연장하지 않습니다.
